# 杀手数独 · Killer Sudoku

> 融合 Killer 笼和值与大小/等值约束（格间/笼间）的网页数独，四档难度，每题唯一且可逻辑求解。

在线体验：<https://killer-sudoku-sakurayoruki.netlify.app/>

## 特性

- **约束系统**：Killer 笼和值 + 大小关系（相邻格 `>`/`<`、相邻笼和值比）+ 等值关系（格间/笼间 `=`）
- **隐藏和值笼**：参与笼间大小/等值约束的笼不显示和值，靠 45 法则或邻接笼推理得到范围
- **四档难度**：简单（33\~38 给定，5 提示）/ 普通（23\~28 给定，4 提示）/ 困难（15\~20 给定，3 提示）/ 专家（6\~10 给定，2 提示），生成时在范围内随机取给定数
- **唯一解 + 逻辑可解**：暴力回溯验证唯一性，逻辑求解器验证每步可推导，不靠猜测
- **约束质量保障**：
  - 单格笼一律不显示和值（与给定数重复属冗余约束）
  - 笼间大小约束带"弹性上限"：和值差超过 `1+N`（N 随和值绝对大小 0→3 递增）的笼对不撒约束，避免"前期就能确认大小关系"的无效约束
  - 隐藏笼优先成对隐藏"和值相近的相邻笼"，保证笼间约束有作用对象
  - **约束跨度限制**：所有笼间/格间约束的端点棋盘距离 ≤ 1（同行/列相邻共享边或对角相邻共享角点），连线只穿两格之间，不会遮挡其他格的候选数
  - **约束有效性 5 规则**（生成端强制，`scripts/audit-puzzles.ts` 可全量审计）：
    1. 有和值笼不可以全部给定格值（挖空时为每个有和值笼预选"牺牲格"必挖）
    2. 相邻两格都给定格值时不撒该对格间大小约束（挖空后自动删除无效约束并补撒替代）
    3. 对角两格都给定格值时不撒该对格间等值约束（同上）
    4. 每一行、每一列、每一宫都至少有一个空格子
    5. 给定数在难度范围内随机（33\~38 / 23\~28 / 15\~20 / 6\~10）
- **离线题库**：easy 20 / normal 20 / hard 10 / expert 10 题，前端按难度抽取，运行时生成作为 fallback
- **约束符号全局防重叠 + 熔断式补回**：撒播后对四类约束（格间/笼间三角、格间/笼间等号）+ 和值标签做二次扫描；任何一对符号距离小于 0.6 格时，按优先级（和值标签 > 笼间等值 > 格间等值 > 笼间大小 > 格间大小）删除低优先级一方，并从候选池补齐到原目标数量；补不回来且唯一性/难度不达标的题目由 pipeline 外层换新题重试。覆盖生成保证题目质量
- **和值标签**：白底黑字 18×14 小标签，无描边，从格子左上角往内移动 2px（盖住笼虚线边框，不盖宫/格实线）；候选数字体在原基础上再缩小一档（最大 0.16/0.12 cell，下限 9px；中心收缩比例 0.7），避免被和值遮挡
- **等值符号 + 笼间大小箭头白底无边框**：等号（蓝色格间/金色笼间，半长 0.10 格）和金色空心三角（tip 0.15 / base 0.07 / half 0.11）统一使用纯白隔离块（无描边）与下方笼边框/网格线分开，线条重合下依然清晰可读；格间与笼间等号两横均沿连线方向延伸（与虚线同向），避免误读为另一对角线的格间标记
- **检查按钮 = 规则校验（非对比答案）**：对当前已填数字执行完整规则判定——① 行/列/宫 Peer 重复 ② Killer 笼和（笼内全填且 `sum≠null` 才判） ③ 格间大小（两格均确定时） ④ 格间等值（两格均确定时） ⑤ 笼间大小（两侧和值均确定：`sum` 已知或笼内全填可求和时） ⑥ 笼间等值（两侧和值均确定时）；违反的格子标红边框 2 秒；信息不足的约束暂不判定（不冤枉玩家）
- **提示按钮右上角红圈剩余次数**：Numpad（数字键盘）的提示按钮在右上角用红色圆角胶囊 + 白字 + 深色细描边显示剩余提示次数（easy 5/normal 4/hard 3/expert 2）；用完徽标隐藏（不显示 0），按钮自动禁用
- **帮助弹窗**：版权、项目简介、玩法（深蓝=格间 / 金色=笼间 颜色区分说明）、符号速查（含一句话记忆口诀）、功能介绍（说明提示红圈与规则检查的语义）
- **Canvas 分层渲染**：网格线、高亮、笼边界、笼标签、大小/等值符号、候选、数字等图层按固定顺序绘制
- **命令模式历史栈**：填值/候选标记封装为 Command，支持撤销/重做/重置本题
- **多选拖动**：按住鼠标划过格子批量选中，输入数字同时填入多格（路径式，只选划过的格）
- **候选保持模式**：有值格输入不同数字时，原确定值降级为候选，与新数字并存为候选
- **暂停遮罩**：空格键切换，遮罩仅覆盖表格本体，左右控制栏可见
- **题目选择弹窗 + 全局编号**：四难度题号连续递增（001→），点击任意题号跳转

## 玩法

- **目标**：填满 9×9 网格，使每行/列/宫 1-9 不重复，且满足所有 Killer 笼和值与大小/等值约束
- **Killer 笼**：虚线框出的格子组，左上角白底黑字标注为格内数字之和，笼内数字不重复
- **颜色分归属、形状分含义**：深蓝色符号表示格与格之间的关系，金色符号表示笼与笼之间的关系；三角比大小，等号表相同
- **格间大小**：相邻格共享边上的深蓝实心三角表示两侧数字大小关系，尖角指向较小的一格
- **笼间大小**：两笼间金色虚线上的空心三角表示两笼和值大小关系，尖角指向较小和值的笼；此类笼不显示和值（隐藏和值笼）
- **格间等值**：两格间蓝色虚线连线中点的蓝色 `=` 表示两格填相同数字（两格必不同行/列/宫）
- **笼间等值**：两笼间金色虚线上的金色 `=` 表示两笼和值相等；此类笼不显示和值
- **操作**：鼠标选格，键盘或右下数字键盘输入；候选模式下数字标为候选；多选拖动批量填值
- **提示**：随机给一个空格填正确答案，次数按难度 5/4/3/2 递减；数字键盘（Numpad）的"提示"按钮右上角红圈徽标显示剩余次数；用完徽标隐藏且按钮禁用；撤销填值不恢复提示次数
- **检查**：按数独规则校验当前所有已填数字（行/列/宫重复、笼和错误、大小/等值关系违反），标红违反的格子 2 秒；**不与答案直接比较**——未填或约束两侧信息不足时不判定（不冤枉玩家）

## 技术栈

- **TypeScript 5** + **Vite 5**（构建/开发服务器）
- **Vitest**（单元测试）
- **Canvas 2D**（渲染，无框架）
- 原生 DOM（UI 控件）

## 开发

### 环境要求

- Node.js 20+

### 安装与运行

```bash
npm install
npm run dev          # 开发服务器 http://localhost:5173
```

### 构建

```bash
npm run build        # 产物输出 dist/
npm run preview      # 预览构建产物
```

### 测试

```bash
npm test             # 求解器/逻辑推理/生成器单元测试
```

### 生成离线题库

```bash
npm run gen-puzzles -- --diff=easy   --n=10             # 覆盖生成
npm run gen-puzzles -- --diff=easy   --n=10 --append    # 追加到现有题库（按 id 去重）
```

题库输出到 `public/puzzles/<难度>.json`，前端启动时加载。追加模式不会覆盖历史题目，适合扩充题库。熔断默认 `maxTries=40` / `timeoutMs=60000`，可用 `--maxTries` / `--timeoutMs` 调整。

## 部署

已配置 [netlify.toml](netlify.toml)：Netlify 连接 GitHub 仓库后，每次 `git push` 自动执行 `npm run build` 并发布 `dist/`。

## 难度评分

```
评分 = maxLevel×80 + steps×0.8 + cageCount×3 + 大小约束数×4
     + 等值约束数×6 + (81-givens)×1.5 + max(0, 20-givens)×10
```

- 简单：0\~200（约束传播可解）
- 普通：200\~400（至少需要 naked-single）
- 困难：400\~600（至少需要数对/45 法则级技巧）
- 专家：≥600（6\~10 给定 + 高密度隐藏笼，极稀给定加成拉高分值）

技巧等级：naked/hidden-single=1，cage-combos=2，数对/45 法则=3，X-Wing=5；每档难度设有最低/最高技巧等级门槛，保证档位区分度。
